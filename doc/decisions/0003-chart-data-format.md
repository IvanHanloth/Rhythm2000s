# 0003 Chart data format

- Status: Accepted
- Date: 2026-10-24

## Context

The MVP chart lived in TypeScript and could only say "the response repeats the call one bar later", with no action types or scene. Charts need to move out of the code into JSON, recording each event's action and the chart's scene.

## Options and decisions

| Question | Options | Decision |
| --- | --- | --- |
| Where the action type goes | Per event / per phrase | **Per event**, so a phrase can mix actions |
| How the response is written | Optional, defaulting to the call / always explicit | **Optional**: omitted means identical to the call; written out only when it differs |
| Where files live | `charts/` bundled / `public/charts/` fetched at runtime | **`public/charts/` at runtime**: charts change without a rebuild, which helps custom charts later, at the cost of handling failed downloads |
| Action naming | By what the player does / by group | By what the player does — **superseded by [ADR 0006](0006-actions-named-after-ui-classes.md)**, which names actions after UI widget classes |

Details in [chart-format.md](../chart-format.md):

- One JSON file per chart, listed in `public/charts/index.json`.
- Times in beats, event positions relative to the start of their bar.
- One set of action IDs shared by all scenes; each scene declares the actions it supports, and using another is an error.
- A `format` version, bumped on incompatible changes.
- An optional `responseGapBeats` (top level, overridable per phrase) adds a rest between call and response; it defaults to 0.

## Consequences

- Charts are fetched and validated at start-up; failing charts are skipped with errors in the console, and a scene without charts says so on screen.
- The synthesised backing is still generated by code; real music will add fields and a version bump.
- Scenes can add rules on top of the shared validation, e.g. desktop scenes require the response to match the call event for event, so each press knows which target it handles.
- Unit tests validate every chart in `public/charts/`.
