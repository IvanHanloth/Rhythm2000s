# 0003 谱面数据格式

- 状态：已采纳
- 日期：2026-10-24（格式的四个关键取舍经用户确认）

## 背景

MVP 的谱面写在 TypeScript 代码里（`buildPopupChart()`），只能表达「跟打 = 示范原样晚 1 小节」，没有动作类型，也看不出它属于哪个场景。改谱面要改代码，不方便调试、做编辑器或让别人写谱。

需要把谱面从游戏代码里拆出来，用 JSON 存储，并记录每个动作的类型和谱面所属的场景（Windows / Mac）。

## 候选方案与决定

| 取舍 | 候选 | 决定 |
| --- | --- | --- |
| 动作类型写在哪一级 | 每个音符单独写 / 每个乐句一个动作 | **每个音符单独写**：一个乐句里可以混用不同动作 |
| 跟打段怎么写 | 可省略、默认照抄示范 / 必须显式写出 | **可省略**：不写就是「与示范完全相同，晚 1 小节」；需要变化时再写 |
| 文件放在哪、怎么加载 | 根目录 `charts/` 打包进游戏 / `public/charts/` 运行时下载 | **`public/charts/` 运行时下载**：不重新构建就能换谱面，方便以后做自制谱；代价是要处理下载失败和等待 |
| 动作怎么命名 | 按玩家做的事（`close-window`）/ 按整组（`popup-close`） | **按玩家做的事**：示范段怎么演由场景决定 |

格式细节见 [chart-format.md](../chart-format.md)。要点：

- 每首谱面一个 JSON 文件，`public/charts/index.json` 列出所有谱面文件。
- 时间一律以拍为单位，事件的拍位置相对于所在小节的开头。
- 动作 ID 是各场景共用的一套英文名字；每个场景声明自己支持哪些动作，谱面用了场景不支持的动作视为错误。
- 文件带 `format` 版本号，格式不兼容地改动时加 1。


## 影响

- 游戏启动时先下载并校验谱面。下载失败或校验出错的谱面会被跳过，错误打印在浏览器控制台；场景没有可用谱面时，在画面上提示。
- 伴奏（合成鼓点）仍由代码按规则生成，不在谱面里。以后接入真正的配乐时，再给格式加字段并升级版本号。
- 场景可以在通用校验之外加自己的规则。例如 XP 场景的「关窗」要求跟打段的动作个数和类型与示范段一致，这样才能知道哪一下关哪个窗口。
- 单元测试会校验 `public/charts/` 下的每个谱面文件。
